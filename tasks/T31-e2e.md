### 決めたこと

1. **データベースは、E2E がサーバーを起動するときは空にする。** 利用者が使っていたデータベースは `playground/data.e2e-backup-<日時>.db` に移して残し(上書きしない)、E2E が作ったもの(目印 `e2e/.cache/playground-database-by-e2e`)は消す。同じ playground の開発サーバーが動いていれば、起動をやめて止めるよう案内する。すでにポートに応答があれば、そのサーバーとデータベースをそのまま使う。根拠: 実測のみ
   - 理由: テストの前提(ロールの利用者・コレクション・検索の設定)を毎回同じに作れる。seed には画像も投稿も無いので、作り直す(seed を入れ直す)利点は無い。
   - テストはデータベースが空であることに頼らない(テストごとの目印 `token` で自分のデータだけを見る、一覧は検索で絞る)。データが残ったデータベースでも全体が通った。
2. ロールの利用者は、SQLite に直接足し、メールアドレスを一時的に入れ替えて開発用ログインを呼んで作る(パスキーを使わずにほかの利用者のセッションを作る API が無いため)。根拠: 実測+公式ドキュメント(`references/emdash/packages/core/src/astro/middleware/auth.ts:437-447`)
3. ルートの `package.json` には `test:e2e`(`playwright test`)だけを足した。入力画像は global setup が無ければ作り、サンプルの投稿はテストが API で作るので、別の script は要らない。
4. 貼り付けのテストは Chromium だけ(Firefox は理由を付けて `test.skip`)。ヘッドレスの Chromium のクリップボードは OS のクリップボードと別で、テストを 20 回続けても macOS のクリップボードは変わらなかった。根拠: 実測のみ
5. console の警告・エラーは、すべてのテストで 0 件であることを確かめる。除くのは EmDash 側の 3 つと、Playwright が原因の Firefox の警告 1 つ。4xx を確かめるテストだけ、Chromium の「Failed to load resource」を除く。根拠: 実測のみ

  - Chromium の貼り付けのテストで、1 回だけ貼り付けた画像が入らなかった。クリップボードへの書き込みの完了を待たずに貼り付けていたので、完了を待つようにした。直したあと、このテストだけを 20 回続けて通った。直す前の形でも再現はできず(単独で 30 回、ほかのテストと並べて 4 回)、原因は確かめられていない(推測のみ)。
  - データが残ったデータベース(先に起動したサーバーを使う)でも 1 回、全体が通った。

### 確かめたこと

- 仕様書 15 章の通しの確認(圧縮 → アップロード → 保存 → サイトの `<img>` の width / height と 100,000 バイト以下 → 一覧のサムネイル → 画像管理ページ)は、両方のブラウザで通った。根拠: 実測のみ
- 処理中の保存(仕様書 18 章)。根拠: 実測のみ(両方のブラウザ)
  - 既存の投稿: 保存の要求のあいだに足した画像は、応答でフォームから外れ、知らせは出ない(ギャラリーは 4 行 → 1 行、単一画像は画像なしに戻る)。外れた画像のエントリは残り、アップロードで参照元が記録されているので、画像管理ページでは「参照元から外された」(`detached`)になる。
  - 新規作成: 最初の保存で widget が作り直され、処理中のアップロードは中断され、残りのファイルは処理されない。知らせも出ない。仕様書 18 章の「推測のみ」を確かめた。
  - 処理中の案内は、単一画像・ギャラリーのどちらも出て、キャンセルボタンの説明になる。
- 開き方ごとのアップロードの `target`: 新規作成・ダッシュボード・コマンドパレットは `{ collection, field }`、一覧から開いた編集と新規作成の保存のあとは `entryId` と `locale: "en"` を含む。新規作成の保存のあと、widget は作り直され(目印の属性が消え、`preview` を取り直し、読み上げの領域は空に戻る)、代替テキストは保存した値で出る。根拠: 実測のみ
- 編集ロック中は、両方の widget のボタン・入力欄が無効で、ドロップ(合成の `drop`)でもつまみのドラッグ(`page.mouse`)でも何も起きない。根拠: 実測のみ
- 狭い画面(390 × 844)で、編集画面の widget は画面の幅に収まり、画像管理ページの表は枠の中で横にスクロールする(ページは横にスクロールしない)。根拠: 実測のみ
- 一覧の一括公開はエントリごとの公開の API を呼び、複製した投稿を一括公開すると、応答のあとに参照元が記録される。根拠: 実測+公式ドキュメント(`references/emdash/packages/admin/src/router.tsx:518-547`)
- プラグイン(`src/**`)の不具合は見つからなかった。根拠: 実測のみ(E2E の範囲で)

### 手で確かめる項目

自動にしなかった項目と理由・手順は [[e2e-playwright-emdash-admin#7. 手で確かめる項目]]。

- スクリーンリーダーでの読み上げ(ヘッドレスに読み上げは無い。E2E は `<output>` の文とアクセシブルな説明までを確かめる)
- OS からの本物のドラッグ(ヘッドレスでは合成のイベントしか送れない)
- ヘッドレスでない Firefox での画像の貼り付け(Firefox のヘッドレスはクリップボードの画像を読めない。ヘッドレスでないと利用者のクリップボードを書き換える)
- 翻訳の切り替え(playground に i18n の設定が無い)
- Safari の実機(E2E は Chromium と Firefox。Safari 相当はモックで確かめた)
- 本番のビルド・`wrangler dev` での動作(E2E は開発サーバーだけ)

### 他のタスクへの影響・サブタスクの候補

- 仕様書 18 章(処理中の保存): 「新規作成の画面では、処理中に保存すると残りの処理が止まる(推測のみ)」は実測で確かめた(処理中のアップロードは中断され、知らせは出ない)。18 章は T31 で変更してよい範囲の外なので、書き換えはリーダーに任せる。既存の投稿で外れた画像は、アップロードのときに参照元が記録されているので、画像管理ページでは `no_owner` でなく `detached`(参照元から外された)になる(実測のみ)。これも書き足すとよい。

- CI で動かすなら、入力画像を `sips` 以外で作る方法が要る(T26 の未解決と同じ)。E2E は macOS でだけ動く。
