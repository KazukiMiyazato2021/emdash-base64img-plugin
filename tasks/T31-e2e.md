# T31 E2E テストを作る

> [!info] 概要
> - 種別: テスト / ウェーブ: 6
> - 着手の条件(依存): [[T26-playground-pages|T26]]、[[T29-plugin-definition|T29]]、[[T30-admin-entry|T30]]

## 目的

仕様書 15 章の E2E を、Chromium と Firefox で作る。

## 作業内容

- [ ] 単一画像: 選択 → 圧縮 → アップロード → 保存 → サイトの `<img>` の width / height と、data URL が 100,000 バイト以下であることを確認する
- [ ] ギャラリー: 複数追加・並べ替え・削除・枚数の上限
- [ ] コンテンツ一覧のサムネイル列
- [ ] 画像管理ページ: 各状態の表示、ゴミ箱への移動、完全削除
- [ ] 異常系: HEIC、SVG、巨大なファイル、Safari 相当(toBlob が PNG を返すモック)、画像が消えた参照を持つ投稿の保存
- [ ] ファイルは `page.setInputFiles(パス)` で渡す(実際のブラウザの `File.type` になる)。HEIC は `sips -s format heic` か `heif-enc` で作れる。途中で切れた JPEG・PNG は Firefox ではデコードできてしまうので、壊れたファイルの確認には乱数のファイルを使う([[T12-input-decode#後続タスク向けのメモ|T12]])
- [ ] テスト用の画像は、アップロードのルート(画面)で作る。seed の `b64_images` を参照する投稿は保存できない([[T16-reference-hook#seed の画像の扱い|T16]])。保存の拒否は 422 `SAVE_REJECTED` で、通知に日本語と英語の文が並ぶ
- [ ] サーバー側の検証: 不正な data URL を API に直接送ると拒否されること
- [ ] 一括公開や複製で参照元の記録(`owners`)を確かめるときは、保存の応答のあと少し待つ(記録の hook は応答のあとに実行される。[[T20-owner-tracking|T20]])
- [ ] (任意)標準の編集画面から `b64_images` を保存すると、保存 hook が拒否すること(422 `SAVE_REJECTED`、通知に日本語と英語の文)([[T19-image-entry-hook#他のタスクへの影響|T19]])
- [ ] 貼り付けの E2E は Chromium だけで行う。Firefox 155 は、合成した `ClipboardEvent` の `clipboardData` が空になり、ヘッドレスではクリップボードの画像も読めない。Chromium では `context.grantPermissions(["clipboard-read", "clipboard-write"])` と、クリックの中での `navigator.clipboard.write` で画像を入れ、ドロップゾーンのボタンにフォーカスして `ControlOrMeta+V` を押す。ドロップは、両方のブラウザで `dispatchEvent("drop", { dataTransfer })` で試せる([[admin-image-input-browser-behavior]])
- [ ] キーボードの操作: Tab でドロップゾーンのボタンに移り、Enter で `filechooser` が開くこと。貼り付けは、ボタンにフォーカスがあるときだけ受け取ること(画像のフィールドが 2 つあるページで、別のフィールドに入らないこと)([[T22-widget-parts#アクセシビリティ|T22]])
- [ ] (任意)実際の(ヘッドレスでない)Firefox で画像を貼り付けられるかは、T22 では確かめていない(利用者のクリップボードを書き換えるため)。確かめるなら手で、ボタンにフォーカスして ⌘V
- [ ] 入力画像(28 個)は git に入れていない。テストの前に `node e2e/fixtures/make-images.ts` で作る(`globalSetup` など。約 1.5 秒)。ファイルと期待する結果(受け付ける 19 個・拒否する 9 個とそのコード)は `e2e/fixtures/README.md`。HEIC の拒否は本物の HEIC(`heic-640x480.heic`・`heic-named-as-jpeg.jpg`)で確かめる。中身が JPEG で拡張子だけ `.heic` のファイルは、JPEG として受け付けられる([[e2e-input-image-fixtures]])
- [ ] 入力画像の一部(JPEG・AVIF・BMP・TIFF・ICO・HEIC)は macOS の `sips` で作る。`sips` の無い環境(Linux の CI など)で動かすなら、作り方を替える([[T26-playground-pages#未解決・サブタスクの候補|T26]])。入力画像やサンプルの投稿を作る script をルートの `package.json` に足すかは、E2E を実行する script を足すときに合わせて決める
- [ ] サイトのページ(`/posts/`・`/posts/<slug>/`)には `data-testid`(`post-card`・`post`・`image-missing` など)と `data-image-id`・`data-field` がある。サンプルの投稿は `playground/scripts/create-sample-posts.ts` で作れる(`--trash-cover` で「画像が見つかりません」の表示も作れる)([[playground-site-pages]])
- [ ] 開発サーバーでは、初めてブラウザが接続したときに Vite が 1 回読み直すことがあるので、`networkidle` を待ってから操作する。管理画面の初回ログインの歓迎ダイアログは少し遅れて出るので、`waitFor` で待ってから閉じる([[T26-playground-pages#他のタスクへの影響|T26]])
- [ ] 実際の管理画面で、編集画面の開き方ごとに、アップロードで送る `target` を確かめる。新規作成(`entryId` と `locale` を送らない)、一覧から開いた編集と翻訳(`?locale=` があり、両方を送る)、ダッシュボード・コマンドパレットから開いた編集(`?locale=` が無く、送らない)。新規作成の保存のあとに widget が作り直されることも確かめる(T27 が実際の管理画面で確かめた。保存のあとの URL は `/_emdash/admin/content/posts/<ID>?locale=en`)([[T23-upload-hook#他のタスクへの影響|T23]]、[[T27-image-widget#実際の管理画面での確認|T27]]、[[emdash-admin-content-editor-url]])
- [ ] コンテンツ一覧のサムネイル列: 1 ページの表示で `thumbnails` の要求が 1 回であること、このプラグインのフィールドの無いコレクション(Pages など)に列が出ないこと(ダッシュボードから SPA で最初に開いたときも)、見出しが管理画面の言語(ja は「画像」)で出ること、画像の無い行の「—」と、記録の無い画像の警告アイコン([[T24-list-column#実際の管理画面での確認|T24]])
- [ ] 画像管理ページ(`/_emdash/admin/plugins/base64-image/images`): ロールごとのボタン(管理者はゴミ箱の画像に「完全に削除」、編集者以上は下書きに「公開」、寄稿者以上は「ゴミ箱に移動」、閲覧者は一覧が 403 で権限の文言)、確認のダイアログのキーボード操作(最初のフォーカスは「キャンセル」、Escape で閉じてボタンに戻る)、操作のあとの表示とフォーカス、「さらに読み込む」、参照元のリンク(`/_emdash/admin/content/<collection>/<ID>?locale=<ロケール>`)。T25 は使い捨てのサイトで確かめた表を残している([[T25-images-page#実際の管理画面で確かめたこと|T25]])
- [ ] 画像管理の一覧で `items: []` のページが続く場合(参照元が 16 件以上の画像)と、`INVALID_CURSOR` のときの読み直し。参照元の多い画像は、サンプルの投稿を作るスクリプトを繰り返すか、同じ画像を多くの投稿に付けて作る([[T21-orphan-routes#T25 への引き継ぎ(応答の形とページ送り)|T21]])
- [ ] 編集ロック: ほかの利用者のロックは、lock の API(`POST /_emdash/api/content/<collection>/<ID>/lock`)を `page.route` で差し替え、`{ data: { enabled: true, holder: {…}, heldByCaller: false } }` を返すと再現できる。ダイアログ(「Open read-only」)を閉じてから、widget のボタンと入力欄が無効なこと、ドロップしても処理が始まらないことを確かめる。処理中の表示(進捗・キャンセル・フォーカス)は、アップロードの要求を `page.route` で止めておくと確かめられる(コードの例は [[emdash-plugin-field-widget#8. 環境と手順]])([[T27-image-widget#他のタスクへの影響|T27]])
- [ ] T27 が実際の管理画面で確かめていないこと: 完全削除した画像を参照したままの投稿の保存(保存 hook ③ の拒否。異常系の「画像が消えた参照を持つ投稿の保存」)、翻訳を切り替えたときの widget の作り直し(spike のサイトが多言語でなかった)。OS からの本物のドラッグは、ヘッドレスでは確かめられない(合成のイベントだけを送れる)([[T27-image-widget#未解決・サブタスクの候補|T27]])
- [ ] ギャラリーの並べ替えのドラッグは、Playwright の `page.mouse`(`down` → `move` を 2 回以上 → `up`)で両方のブラウザで動く。落とす位置の線は、行の `style.boxShadow` で確かめられる。編集ロックは、lock の API の差し替えのほか、widget を包む `fieldset` に `disabled` を付けても試せる([[T28-gallery-widget#他のタスクへの影響|T28]]、[[gallery-widget-reorder-focus]])
- [ ] 処理中の保存: `page.route` で手動の保存(`skipRevision` の無い `PUT`)の応答を遅らせると、保存の要求のあいだに足した画像がフォームから外れることを再現できる(仕様書 18 章)。処理中に案内(T28-2 で足す)が出ることを、単一画像とギャラリーの両方で確かめる。新規作成の画面で処理中に保存すると、widget が作り直されて残りの処理が止まるとみられる(推測のみ。確かめる)([[gallery-widget-reorder-focus#4. 処理中に「Save」を押したとき(EmDash の挙動)]])
- [ ] T28 が確かめていないこと: OS からの本物のドラッグ(Playwright の合成でないもの)と、スクリーンリーダーでの読み上げ(並べ替え・削除・差し替えの `<output>`)。確かめるなら手で行う([[T28-gallery-widget#未解決・サブタスクの候補|T28]])
