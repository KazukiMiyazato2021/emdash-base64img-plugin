# T31 E2E テストを作る

> [!info] 概要
> - 種別: テスト / ウェーブ: 6

## 目的

仕様書 15 章の E2E を、Chromium と Firefox で作る。

## 作業内容

- [ ] 単一画像: 選択 → 圧縮 → アップロード → 保存 → サイトの `<img>` の width / height と、data URL が 100,000 バイト以下であることを確認する
- [ ] ギャラリー: 複数追加・並べ替え・削除・枚数の上限
- [ ] コンテンツ一覧のサムネイル列
- [ ] 画像管理ページ: 各状態の表示、ゴミ箱への移動、完全削除
- [ ] 異常系: HEIC、SVG、巨大なファイル、Safari 相当(toBlob が PNG を返すモック)、画像が消えた参照を持つ投稿の保存
- [ ] ファイルは `page.setInputFiles(パス)` で渡す(実際のブラウザの `File.type` になる)。HEIC は `sips -s format heic` か `heif-enc` で作れる。途中で切れた JPEG・PNG は Firefox ではデコードできてしまうので、壊れたファイルの確認には乱数のファイルを使う([[T12-input-decode#後続タスク向けのメモ|T12]])
- [ ] テスト用の画像は、アップロードのルート(画面)で作る。seed の `b64_images` を参照する投稿は保存できない([[T16-reference-hook#seed の画像の扱い|T16]])。保存の拒否は 422 `SAVE_REJECTED` で、通知に日本語と英語の文が並ぶ
- [ ] サーバー側の検証: 不正な data URL を API に直接送ると拒否されること
- [ ] (任意)標準の編集画面から `b64_images` を保存すると、保存 hook が拒否すること(422 `SAVE_REJECTED`、通知に日本語と英語の文)([[T19-image-entry-hook#他のタスクへの影響|T19]])

## 完了条件

- [ ] 両方のブラウザで、すべてのシナリオが通る
