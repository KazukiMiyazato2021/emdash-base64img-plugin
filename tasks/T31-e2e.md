# T31 E2E テストを作る

> [!info] 概要
> - 種別: テスト / ウェーブ: 6

> - 仕様: [[base64-image-plugin-spec#15. リポジトリ構成・ツール・テスト|仕様書 15章]]

## 目的

仕様書 15 章の E2E を、Chromium と Firefox で作る。

## 作業内容

- [ ] 単一画像: 選択 → 圧縮 → アップロード → 保存 → サイトの `<img>` の width / height と、data URL が 100,000 バイト以下であることを確認する
- [ ] ギャラリー: 複数追加・並べ替え・削除・枚数の上限
- [ ] コンテンツ一覧のサムネイル列
- [ ] 画像管理ページ: 各状態の表示、ゴミ箱への移動、完全削除
- [ ] 異常系: HEIC、SVG、巨大なファイル、Safari 相当(toBlob が PNG を返すモック)、画像が消えた参照を持つ投稿の保存
- [ ] ファイルは `page.setInputFiles(パス)` で渡す(実際のブラウザの `File.type` になる)。HEIC は `sips -s format heic` か `heif-enc` で作れる。途中で切れた JPEG・PNG は Firefox ではデコードできてしまうので、壊れたファイルの確認には乱数のファイルを使う([[T12-input-decode#後続タスク向けのメモ|T12]])
- [ ] テスト用の画像は、アップロードのルート(画面)で作る。seed の `b64_images` を参照する投稿は保存できない([[T16-reference-hook#seed の画像の扱い|T16]])。保存の拒否は 422 `SAVE_REJECTED` で、通知に日本語と英語の文が並ぶ
- [ ] サーバー側の検証: 不正な data URL を API に直接送ると拒否されること
- [ ] 一括公開や複製で参照元の記録(`owners`)を確かめるときは、保存の応答のあと少し待つ(記録の hook は応答のあとに実行される。[[T20-owner-tracking|T20]])
- [ ] (任意)標準の編集画面から `b64_images` を保存すると、保存 hook が拒否すること(422 `SAVE_REJECTED`、通知に日本語と英語の文)([[T19-image-entry-hook#他のタスクへの影響|T19]])
- [ ] 貼り付けの E2E は Chromium だけで行う。Firefox 155 は、合成した `ClipboardEvent` の `clipboardData` が空になり、ヘッドレスではクリップボードの画像も読めない。Chromium では `context.grantPermissions(["clipboard-read", "clipboard-write"])` と、クリックの中での `navigator.clipboard.write` で画像を入れ、ドロップゾーンのボタンにフォーカスして `ControlOrMeta+V` を押す。ドロップは、両方のブラウザで `dispatchEvent("drop", { dataTransfer })` で試せる([[admin-image-input-browser-behavior]])
- [ ] キーボードの操作: Tab でドロップゾーンのボタンに移り、Enter で `filechooser` が開くこと。貼り付けは、ボタンにフォーカスがあるときだけ受け取ること(画像のフィールドが 2 つあるページで、別のフィールドに入らないこと)([[T22-widget-parts#アクセシビリティ|T22]])
- [ ] (任意)実際の(ヘッドレスでない)Firefox で画像を貼り付けられるかは、T22 では確かめていない(利用者のクリップボードを書き換えるため)。確かめるなら手で、ボタンにフォーカスして ⌘V
- [ ] 入力画像(28 個)は git に入れていない。テストの前に `node e2e/fixtures/make-images.ts` で作る(`globalSetup` など。約 1.5 秒)。ファイルと期待する結果(受け付ける 19 個・拒否する 9 個とそのコード)は `e2e/fixtures/README.md`。HEIC の拒否は本物の HEIC(`heic-640x480.heic`・`heic-named-as-jpeg.jpg`)で確かめる。中身が JPEG で拡張子だけ `.heic` のファイルは、JPEG として受け付けられる([[e2e-input-image-fixtures]])
- [ ] 入力画像の一部(JPEG・AVIF・BMP・TIFF・ICO・HEIC)は macOS の `sips` で作る。`sips` の無い環境(Linux の CI など)で動かすなら、作り方を替える([[T26-playground-pages#未解決・サブタスクの候補|T26]])。入力画像やサンプルの投稿を作る script をルートの `package.json` に足すかは、E2E を実行する script を足すときに合わせて決める
- [ ] サイトのページ(`/posts/`・`/posts/<slug>/`)には `data-testid`(`post-card`・`post`・`image-missing` など)と `data-image-id`・`data-field` がある。サンプルの投稿は `playground/scripts/create-sample-posts.ts` で作れる(`--trash-cover` で「画像が見つかりません」の表示も作れる)([[playground-site-pages]])
- [ ] 開発サーバーでは、初めてブラウザが接続したときに Vite が 1 回読み直すことがあるので、`networkidle` を待ってから操作する。管理画面の初回ログインの歓迎ダイアログは少し遅れて出るので、`waitFor` で待ってから閉じる([[T26-playground-pages#他のタスクへの影響|T26]])
